# Contributing to Execora

We love your input! We want to make contributing to Execora as easy and transparent as possible, whether it's:

- Reporting a bug
- Discussing the current state of the code
- Submitting a fix
- Proposing new features

## Development Workflow

1. **Fork** the repository.
2. **Clone** your fork.
3. **Create a branch** for your changes.
4. **Make your changes**.
5. **Verify** your changes by running the app on an emulator or physical device.
6. **Commit** your changes with clear and descriptive messages.
7. **Push** to your fork.
8. **Submit a Pull Request**.

## Coding Standards

- Follow the [Kotlin Style Guide](https://kotlinlang.org/docs/coding-conventions.html).
- Use Jetpack Compose best practices.
- Keep Python logic modular within the `src/main/python` directory.
- Ensure any new features are also documented.

## Feature Requests

If you have a feature idea, please open an issue first to discuss it. This ensures that the community is interested and that the implementation aligns with the project's goals.

## Bug Reports

When reporting a bug, please include:
- A clear description of the issue.
- Steps to reproduce.
- Expected vs. Actual behavior.
- Device information and Android version.
